# 长文档大纲完整性修复

用户反馈长文档大纲只显示开头几个标题。复现：101,292 字符、100 个标题的笔记，大纲仅返回 3 项；新建 CodeMirror EditorState 的 syntaxTree 长度只有 3035。编辑器使用有限预算和按需解析，大纲对独立创建的 state 提取一次后没有后续完整解析，因而被截断。

extractHeadings 在独立 outline.ts 中使用现有 GFM Markdown 解析器对全文生成完整树，以 DocInput/Text 保持正文行号；仅遍历标题，跳过 YAML、围栏/缩进代码和 HTML 块。React 通过 Worker 调用该函数，延迟 150ms 合并输入并终止过期 Worker；同一笔记更新时保留旧大纲，切换笔记时不展示上一笔记的结果。加载和失败有对应空状态提示。大纲不依赖编辑器视口或后台解析进度；即时预览仍沿用原按需语法树。没有修改侧栏外观或笔记原文。

测试先复现失败，再实现修复。99 项单元测试与正式构建通过。新增长文档回归覆盖所有 100 个标题、末尾 Setext、代码伪标题忽略及追加标题。临时笔记库 Electron 验证 6 个场景通过：未滚动时标题已完整、末尾标题跳转至第 397 行、编辑后大纲更新并保存、长短文档切换、阅读模式完整、较大文档全文解析时主界面计时器仍持续执行（本次 107 次），并提取到末尾标题。确认生产构建 Worker 在 Electron 本地页面正常加载，无页面异常。

复核指出主线程全量解析在超长文档中可能影响输入，已由 Worker 方案解决；没有在主线程按输入重新全量解析的回退路径。独立复核结论为 ship。

执行 `npm run test:outline` 可重现，报告和截图在 `.impeccable/review/outline/`。改动未打包或发布，Windows 未实机验证。
