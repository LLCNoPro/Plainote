# Mermaid 图表导出 DOCX

用户确认实现前一轮评估方案：导出时将 Mermaid 代码转成浅色高清 PNG 并嵌入 Word，原文不变，失败指出图表并终止，不依赖 Mermaid CLI 或额外浏览器。

复用 Mermaid SVG 引擎，抽取为独立模块。使用无 preload、无 Node 权限的隐藏 Electron 窗口加载专用本地 Vite 页面，生成浅色 SVG 图片并以 2 倍尺寸截图为 PNG；图片含 foreignObject，采用截图避免 canvas 污染问题。图像资源及渲染均离线，单图设超时和像素预算，导出完成或失败销毁窗口。

主进程调用 Pandoc 将临时 Markdown 转 JSON AST，只替换语言为 mermaid 的 CodeBlock 节点为 Image。这样引用/列表中的图表保持上下文，普通代码和 YAML 不误改。按图片比例设置适配现有参考模板的尺寸（最大 5.7 英寸宽、8.5 英寸高），保留原文相对图片资源查找路径。

所有中间文件写入目标文件所在目录中的唯一临时目录，最终 DOCX 完成后重命名至用户选定路径；失败不覆盖原目标并清理临时文件。复用现有模板、Pandoc 配置和保存对话框，不增加设置项。

测试先补失败用例：AST 仅替换 Mermaid、上下文保持、失败定位；实际 Electron + Pandoc 导出多张图与含 HTML 换行的状态图，检查 DOCX 压缩包中的 PNG/关系/版面尺寸、普通代码和原文保留、取消和失败清理；LibreOffice 渲染验证文档版面。此前方案比较已完成，直接进入实现。

## 实现与验证

实现完成。图表段落使用模板已有 Figure 样式居中，避免正文字体的首行缩进导致宽图越界；引用及列表每层预留 0.6 英寸缩进空间。Pandoc 超时后强制结束并等待子进程退出，再清理临时目录，防止 Windows 下文件句柄竞争。没有图表时不会创建隐藏窗口，磁盘原笔记被删除但仍在内存的正文也可导出。

97 项单元测试与正式构建通过，含新增 AST、嵌套宽图、错误序号及实际子进程超时验证。10 项 DOCX 桌面场景通过：流程图、状态图含 HTML 换行、引用/列表图表生成 PNG，原有相对图片读取，DOCX 内嵌图片及尺寸，深色界面导出浅色，普通代码/原文保留，错误不覆盖目标，取消/清理/隐藏窗口销毁，无图表与磁盘原文缺失导出，嵌套宽图。此前 10 项 Mermaid 桌面预览回归通过，无页面异常或外部 HTTP 请求。

用 LibreOffice 将实际导出文件渲染为 PDF 并逐页检查：3 页综合文档、1 页嵌套宽图均无图表越界或截断。检查产物位于 `.impeccable/review/mermaid-docx/`（`export.docx`、`nested-wide.docx`、PDF、页面 PNG 和报告），通过 `npm run test:docx` 可重现。Windows 未执行实机验证；没有打包或发布安装包。
