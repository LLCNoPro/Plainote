# 素记 Plainote 产品与技术规划

日期：2026-10-12  
状态（2026-10-17 更新）：已采用 Electron + React + TypeScript + CodeMirror 6，阶段 A 核心功能完成，阶段 B/C 部分完成，阶段 D 已有打包发布配置。当前构建、51 项单测及 41 项 macOS 桌面检查通过；Windows 与未覆盖功能不能视为已验收。逐项进度见[功能进度与桌面回归核对](2026-10-17-progress-audit.md)。下文保留原规划目标，具体偏差以该核对记录为准。

## 1. 定位与已确定需求

素记是一款面向工作场景、本地优先的 Markdown 桌面笔记软件。核心价值是写作流畅、工作资料容易找回、文件可长期使用。

- 第一版支持 macOS 与 Windows。
- 默认使用即时预览，并提供源码模式切换。
- 主要用途是会议记录、项目资料、工作日志和简单待办。
- 第一版只考虑单台电脑，不开发账户、同步或服务端。
- 直接打开现有 Obsidian 笔记库，无需导入转换。
- 现有笔记以普通 Markdown、双向链接和图片为主，不依赖插件兼容。

## 2. 产品结构

左侧展示文件目录、搜索和常用笔记；中间为多标签编辑区；右侧为大纲与反向链接。两侧面板可以收起。视觉方向是安静、清晰、低干扰，尊重各平台的窗口与快捷键习惯。

主要流程：打开笔记库 → 选择项目文件夹 → 用模板新建笔记 → 输入正文、粘贴截图、记录待办 → 自动保存 → 通过搜索、目录或链接找回。

首次使用只需要选择或新建一个文件夹。打开已有库时展示现有目录与索引进度，不批量修改笔记。

## 3. 第一版功能

| 模块 | 范围 |
| --- | --- |
| 笔记库 | 打开文件夹、最近使用的库、切换笔记库 |
| 文件管理 | 创建、重命名、移动、删除；文件目录树 |
| 编辑 | 即时预览、源码模式、撤销重做、文内查找 |
| 常用语法 | 标题、强调、引用、列表、任务列表、表格、代码块、链接、图片 |
| 导航 | 多标签、前进后退、按标题快速打开、大纲 |
| 搜索 | 全文搜索、文件夹过滤、结果上下文 |
| 工作记录 | 普通 Markdown 模板；内置会议记录、项目文档、工作日志 |
| 附件 | 图片粘贴与拖入、相对路径引用、打开其他附件 |
| 关联 | 双向链接补全、反向链接、标题与块链接定位 |
| 偏好 | 明暗主题、字号、字体、附件保存位置 |
| 可靠性 | 自动保存、保存状态、外部变更检测、冲突处理、删除恢复、有限历史记录 |

原规划暂不加入图谱、插件市场、完整任务管理、移动端、内置同步、Canvas 或 Excalidraw 编辑器。AI 已于后续独立计划中加入并实现。已有不支持的文件保持原样；通过系统关联应用打开附件仍是待实现目标。

模板直接生成 Markdown，不执行脚本。任务管理仅包含勾选框，不支持跨库任务查询与提醒。

## 4. Obsidian 兼容约定

1. Markdown 文件是正文的唯一来源，应用数据库不能成为唯一存储。
2. 保留目录结构、文件名、未知语法和未编辑区域；不在保存时统一格式化整篇笔记。
3. 支持 `[[笔记]]`、`[[目录/笔记]]`、`[[笔记|显示名称]]` 和标准 Markdown 链接。
4. 支持标题与块引用，以及 `![[图片.png]]` 和普通 Markdown 图片引用。
5. 保留 YAML frontmatter，识别常用标签和别名；暂不提供复杂属性编辑器。
6. 不修改 `.obsidian` 或其他已有工具的配置。素记的设置和索引放在应用数据目录，按笔记库隔离。
7. 同名笔记需要明确、可测试的解析规则；存在无法唯一确定的目标时提示选择，不任意跳转。
8. 重命名与移动先分析受影响链接，只修改能确定目标的引用；批量修改记录操作日志，失败时允许恢复。
9. 自定义附件目录由用户指定；打开已有库时不自动搬迁已有附件。

兼容性以实际语法样例验证，不宣称完整兼容 Obsidian 或其插件生态。

## 5. 技术方案比较与建议

| 方案 | 优势 | 成本与限制 |
| --- | --- | --- |
| Electron + TypeScript | 自带 Chromium 与 Node.js；两平台使用一致的浏览器引擎，适合优先打磨编辑器 | 浏览器运行时带来安装体积和内存成本，需实测控制 |
| Tauri + TypeScript + Rust | 复用系统 WebView，可减少随应用分发的运行时内容 | 需维护 Rust 侧能力，并验证不同平台 WebView 的编辑差异 |
| 两套原生客户端 | 更直接地使用平台控件与系统能力 | 两套界面与编辑集成增加开发和长期维护成本 |

建议第一版采用 Electron + React + TypeScript，编辑器使用 CodeMirror 6。此推荐是基于当前优先级的工程判断：先实现稳定的跨平台编辑与文件兼容，再用实测结果优化资源占用。

CodeMirror 提供装饰机制，可在保留 Markdown 原文的同时呈现格式，但不会自动提供完整的 Obsidian 式即时预览。需要自行实现 Markdown 解析、光标所在区域的源码显露、图片组件与链接交互，并优先验证中文输入。

技术选型已落地；当前依赖及锁定版本以 package.json 与 package-lock.json 为准。

## 6. 架构与数据流

- 界面层：目录、标签页、搜索面板、大纲、反向链接、偏好设置。
- 编辑层：Markdown 文本、即时预览扩展、源码模式、编辑历史。
- 本地服务层：文件读写、文件监听、附件写入、恢复记录、系统集成。
- 索引层：文件路径、标题、别名、标签、正文搜索、链接关系；可重建。

文件系统 → 后台扫描与增量索引 → 目录、搜索与链接面板。

编辑操作 → 内存文档 → 串行保存队列 → 文件系统 → 更新索引。

索引工作放在后台工作进程，避免阻塞输入。第一阶段可先使用内存索引验证语义；大库阶段评估 SQLite FTS 等持久化方案，并验证中文搜索行为。

渲染进程通过有限的接口请求本地文件操作，不直接开放完整 Node.js 能力。笔记中的 HTML 与链接按明确规则处理；不执行笔记内容中的脚本。

## 7. 保存与错误处理

- 输入时明确区分“未保存”“已保存”“保存失败”，自动保存不能制造虚假的成功状态。
- 写入前核对磁盘版本；通过同目录临时文件写入与替换降低半写入风险，平台行为需要分别验证。
- 同一文件的写入串行化，防止旧内容覆盖新内容。
- 文件被外部修改且当前文档未修改时重新加载；双方都修改时保留两份内容，提供比较与选择。
- 保存失败保留内存内容，并提供重试和另存为。
- 删除默认进入系统回收站；失败时不自动退化为永久删除。
- 历史恢复设定数量与容量上限，说明其范围，避免把局部恢复能力当作完整备份。
- 异常退出恢复需要保存未落盘编辑状态；恢复记录与正文文件分开管理。

## 8. 分阶段交付

### 阶段 A：编辑与文件验证

完成桌面壳、打开文件夹、目录树、单笔记编辑、源码模式、基础即时预览、自动保存与保存失败反馈。使用笔记库副本验证文件读写。

出口条件：中文输入、撤销重做、复制粘贴、长文滚动正常；未编辑笔记不发生变化；保存失败时内容仍可找回。

### 阶段 B：工作笔记闭环

完成多标签、文件管理、搜索、快速打开、模板、图片附件与大纲。此阶段开始分别在 macOS 和 Windows 检查构建与核心交互。

出口条件：能够完整记录一场会议、管理项目资料，并通过搜索找回历史信息。

### 阶段 C：链接兼容与恢复

完成链接补全、反向链接、标题和块定位、重命名更新、外部变更、冲突提示、删除恢复与异常退出恢复。

出口条件：真实 Obsidian 笔记样例中链接与图片正确；未知语法保留；移动与重命名不会静默造成错误关联。

### 阶段 D：可发布版本

完善偏好与视觉细节，测量大库性能，完成两平台安装包、签名与 macOS 公证方案。发布所需证书与账号在分发阶段再确认。

出口条件：两平台安装、打开、编辑、搜索、恢复均通过；明确已知限制。Windows 需要 Windows 实机或 CI 验证，不能仅凭 macOS 上的构建推断可用。

## 9. 验收与测试

- 兼容样例：中文路径、空格路径、同名笔记、别名、标题与块引用、两种图片语法、YAML、未知代码块和不同换行符。
- 文件可靠性：写入失败、外部修改、快速连续保存、重命名中断、删除失败、异常退出与索引重建。
- 编辑体验：两平台中文输入法、组合输入期间的即时预览更新、光标位置、撤销重做、图片附近编辑和长文。
- 搜索性能：用小库和约一万篇笔记的测试库分别测量启动、搜索、索引与输入响应；正式承诺性能指标前记录硬件和数据条件。
- 开发顺序按依赖推进，不把缺少实际验证的时间估算视为交付承诺。

## 10. 主要风险与后续决策

最大风险是即时预览影响输入、旧库链接解析错误以及文件操作损坏内容，因此阶段 A 优先验证编辑，阶段 C 优先验证兼容与恢复。

技术栈、基础视觉、图标及安装分发配置已落地。后续重点是补齐第一版剩余能力、确定性能验收阈值、完成 Windows 交互验证与签名/公证；具体进度以 2026-10-17 核对记录为准。
